このマニュアルでできるようになること：Claude Codeに動画制作を任せて、自社ブランドの色・フォントを守ったまま、告知動画を自分の手で1本完成させます。

このマニュアルの特徴：一般的なノウハウ集ではありません。実際にこの手順で動画を作った人（棚原）が、その場で詰まった箇所・実際にAIへ投げた質問・解決できた方法を、そのままQ&Aとして載せています。同じところで詰まっても、この先を読めばそのまま解決します。

Step 0｜前提（始める前に）

何ができるようになるか

  • 自社サイトの色・フォント・トーンをAIに学習させ、以降の動画がすべて自社ブランド準拠で出てくる状態を作れます
  • 実物のスクリーンショットや写真を使って、自社商品・サービスの告知動画（横型・縦型）を作れます
  • Premiere ProやCapCutのような編集ソフトの操作を覚える必要はありません。AIに「日本語で」頼むだけです

所要時間の目安

到達点所要時間
動作確認（Step1〜3）30〜90分
自社ブランドで告知動画1本が完成（Step1〜8）半日〜1日

判断は不要です。上から順番に進めるだけで到達します。

必要なもの・費用

  • Mac または Windows のパソコン（本マニュアルはMac手順で記載）
  • Claude Code（AIとチャットしながら作業を頼めるツール。導入済み前提）
  • 自社サイトのURL（お持ちでない場合はStep4のQ&Aを参照）
  • 費用：ソフト自体は無料。BGM生成等でAIサービスの利用枠を使う場合があります（Step8のQ&A参照）

本マニュアルの範囲

Step1〜9で「自分で動画を1本作れる状態」まで到達します。「AIに動画制作を任せる仕組みを組織に定着させる」ところ（AI社員化・運用の型づくり）は本マニュアルの範囲外です。巻末で1〜2行だけ触れます。

Step 1｜環境構築（所要15分）

この工程で何をするか

動画を作るための土台となる2つの道具（Node.js・FFmpeg）をパソコンに入れます。専門知識は不要です。すべてClaude Codeに頼めます。

入っているか確認するコマンド

ターミナル（コマンドを打ち込む画面）を開いて、以下をそのまま貼り付けてください。

node -v
ffmpeg -version | head -1

表示されるはずの画面：バージョン番号（例：v22.x.x）が表示されれば入っています。「command not found」と出た場合は次の手順に進んでください。

入っていない場合のインストール（Macの場合）

brew install ffmpeg

Node.jsは公式サイトのインストーラーを使うのが最も確実です。

一番かんたんな方法（推奨）

Claude Codeに以下の文章をそのままコピペして頼んでください。

Node.js と FFmpeg を入れて。動作確認まで頼む。

Claude Codeが自動でインストールし、動作確認まで行います。エラーが出た場合は、エラーメッセージ全文をそのままコピーしてClaude Codeに貼り返してください。それだけで直ります。

覚えておくこと

道具の使い方を細かく覚える必要はありません。「相棒（Claude Code）への頼み方」を覚えることが、この先すべてのステップで役立ちます。

Step 2｜スキル導入

この工程で何をするか

Claude Codeに「動画制作の専門知識パック（スキル）」を追加します。

作業用フォルダを作る

以下をそのままターミナルに貼り付けてください。

mkdir -p ~/HyperFrames_Trial && cd ~/HyperFrames_Trial

表示されるはずの画面：何も表示されません（エラーが出なければ成功です）。

スキル導入コマンド

npx skills add heygen-com/hyperframes --all --full-depth

表示されるはずの画面：インストール処理のログが流れ、最後に完了メッセージが出ます。

  • --full-depth：最新版を確実に取得するためのおまじないです。省略すると古いコピーが入ることがあるため、必ず付けてください
  • --all：動画制作に使える機能を全部（20種類）まとめて入れる指定です

完了後にやること

Claude Codeを再起動してください。再起動しないと、新しく入った機能（スラッシュコマンド）が使えません。

よくある詰まりポイントと対処法

症状：/hyperframes と入力しても「Unknown command（不明なコマンド）」と出る

原因：スキルを入れたフォルダと、今Claude Codeを起動しているフォルダが違います

対処：cd ~/HyperFrames_Trial を実行してから、そのフォルダでClaude Codeを起動し直してください

症状：普段使っている業務フォルダでも使いたい

対処：最初のうちは ~/HyperFrames_Trial フォルダの中だけで練習することをお勧めします。慣れてから、別のフォルダにも同じ手順でスキルを入れれば使えるようになります

Step 3｜最初の1本（動作確認）

この工程で何をするか

本当に動くかどうかを確認するために、内容を気にせず10秒の動画を1本作ってみます。

そのまま貼り付けるプロンプト（AIへの指示文）

Claude Codeに以下をそのまま貼り付けてください。

/hyperframes を使って、10秒のプロダクト紹介動画を作ってください。
黒背景にタイトルがフェードインして、控えめなBGMが流れる構成で。
サイズは1920x1080でお願いします。

表示されるはずの画面・結果

「HyperFrames」というロゴだけが表示される、地味な10秒動画が完成します。

これは失敗ではありません。動作確認としては100点満点です。タイトルの中身も内容も指定していないため、AIが仮の内容を入れているだけです。

よくある勘違いと対処法

症状：出来上がった動画が地味・意味不明。プロンプトが間違っていた？

対処：間違っていません。「10秒／黒背景／タイトルがフェードイン／プロダクト紹介」としか指定していないので、これが正しい結果です。ここで満足度を求めず、次のStep4に進んでください

症状：具体的な内容の動画を作りたい

対処：Step4で自社ブランドを1回登録すれば、以降は「20秒の紹介動画作って」と頼むだけで自社ブランド準拠の動画が出るようになります。今は先に進んでください

Step 4｜自社ブランド抽出（DESIGN.md）

この工程で何をするか

自社サイトの色・フォント・文章のトーンをAIに読み取らせて、DESIGN.md（ブランドの設計図ファイル）という1つのファイルにまとめます。これを1回作れば、以降の動画すべてが自社ブランド準拠で出るようになります。

そのまま貼り付けるプロンプト

[あなたのサイト] の部分だけ、自社サイトのURLに書き換えてください。それ以外は変更不要です。

https://[あなたのサイト] から僕のブランドの DESIGN.md を作ってください。

ライブのHTMLと、実際に読み込まれているCSSファイルを取得して、
色のhexコードとフォント名はCSSから一字一句そのまま抜き出すこと。
スクリーンショットから色を推測するのは禁止です。
フォントは代替候補ではなく、実際に読み込まれているものを報告してください。
サイトの実際の見出しを3〜5本読んで、そこから声とトーンのルールを導いてください。

中身は絞ってください。
- 役割と組み合わせ付きの色を4〜6個
- 文字の役割を2〜3個
- 余白と角丸と影の値
- 「常に〜する」「絶対に〜しない」という形のルール

最後に、それぞれの色とフォントをCSSのどこで見つけたか出典を列挙して、
出典を示せない項目は削除してください。

出力は DESIGN.md というファイル名で保存してください。

なぜこの文言が必要か（変更しないでください）

  • 「スクリーンショットから色を推測するのは禁止」：AIが見た目だけで色を当てずに、実際のコード（CSS）から正確な数値を取ってくるための指定です
  • 「出典を示せない項目は削除」：AIが間違った情報を作り出すこと（ハルシネーション）を防ぐための指定です

表示されるはずの画面

DESIGN.md というファイルが作成され、以下のような中身になります（イメージ）。

colors:
  canvas: "#ffffff"
  ink: "#10151c"
  navy-deep: "#070f1e"
  accent: "#1f3a66"
typography:
  display: [フォント名] (weight 700)
  body:    [フォント名] (weight 400)
  label:   [フォント名] (weight 600, uppercase)
radius: 0（角ゼロ）
shadow: none（影ゼロ）

よくある詰まりポイントと対処法

症状：自社サイトを持っていない

対処：色コード・フォント名・話し方の雰囲気を文章でClaude Codeに伝えてください。それだけで同等のDESIGN.mdが作れます。SNSや過去の資料で使ってきた配色を伝えるだけでも十分です

症状：サイトのCSS取得に失敗する

対処：手元にサイトのHTML/CSSファイルがあれば、そのファイルの場所（パス）を直接Claude Codeに伝えてください。それも難しい場合は、上記と同様に文章で色・フォントを伝えてください

Step 5｜FRAME.md変換

この工程で何をするか

Step4で作ったDESIGN.mdを、動画の「動き方のルール」を含んだFRAME.mdというファイルに変換します。ブラウザ操作のみで完了します。

手順（番号順にそのまま実施）

  1. ブラウザで https://hyperframes.dev/design を開いてください
  2. Step4で作ったDESIGN.mdをアップロードしてください
  3. 変換が終わるまで待ってください（下記「待ち時間の目安」参照）
  4. zipファイルが自動でダウンロードされます（ファイル名の末尾が -frame-pack.zip になっています）

表示されるはずの画面

ダウンロードフォルダに [サイト名]-frame-showcase-frame-pack.zip というファイルができます。中には3つのファイルが入っています。

ファイル名内容
FRAME.md本命の成果物。次のStep6で使います
frame-showcase.html見本ファイル。ブラウザで開くと動きのサンプルが見られます
README.html使い方の説明ファイル

よくある詰まりポイントと対処法

症状：途中でログインを求められる

対処：GitHubアカウントでログインすれば進めます。見た目上は基本ログイン不要ですが、求められたらGitHubログインで問題ありません

症状：画面に「Composing... → list_files → learn_skill → read_file → Ionizing」という表示のまま止まっている

対処：これは正常な処理中の表示です。1〜3分待ってください。5分待っても変わらない場合のみ、ブラウザを再読み込みして最初からアップロードし直してください

Step 6｜frame.md配置（ここで詰まりやすい注意点あり）

この工程で何をするか

Step5でダウンロードしたzipファイルを展開し、FRAME.mdを作業フォルダに配置します。Macを使っている場合、ここで詰まりやすいので必ず以下の手順通りに行ってください。

注意点（Macだけの現象）

Macの標準的なファイル管理の仕組み（APFS）は、大文字と小文字を区別しません。そのため FRAME.md と frame.md は「同じファイル」として扱われ、普通にコピーしようとするとエラーになります。

そのまま貼り付けるコマンド

[サイト名] の部分は、Step5でダウンロードしたzipファイルの実際の名前に置き換えてください。

cp ~/Downloads/[サイト名]-frame-showcase-frame-pack.zip ~/HyperFrames_Trial/
cd ~/HyperFrames_Trial
unzip -o [サイト名]-frame-showcase-frame-pack.zip -d frame-pack/
cp frame-pack/FRAME.md ./frame.md

表示されるはずの画面：unzip実行後にファイル一覧が表示され、最後のコマンド実行後は何も表示されません（エラーが出なければ成功です）。

なぜこの手順が正解か

  • 大文字のFRAME.mdの原本はframe-pack/フォルダの中にそのまま残します（消しません）
  • 作業フォルダの直下には、小文字のframe.mdとして配置します。HyperFramesは小文字のファイル名しか自動で見つけられない仕組みだからです

よくある詰まりポイントと対処法

症状：cp コマンドを実行するとエラーになる

対処：上記のコマンドを一字一句そのままコピペしてください。手順通りに行えばエラーは起きません。原本はframe-pack/側に残っているので、失敗してもやり直せます

Step 7｜ブランドリール（frame.md準拠テスト）

この工程で何をするか

Step6で配置したframe.mdを実際に使って、自社ブランドの色・フォント・動きが反映された20秒の動画を1本作ります。

そのまま貼り付けるプロンプト

/hyperframes
frame.md を読んでください。
これを体現する20秒のブランドリールを1920x1080で作ってください。
ロゴとカラーパレットで始まり、タイポグラフィの見本を見せて、
このデザインシステムでUIカードを1枚組み立てて、最後はロゴで締める構成で。
すべての登場・退場・転換は frame.md のモーション言語に従ってください。

表示されるはずの画面

ロゴ・色見本・文字見本・部品見本の5シーン程度からなる動画が完成します。自社ブランドが「白ベース・落ち着いた雰囲気」であれば、動画も静かな仕上がりになります。それが正解です。

よくある勘違いと対処法

症状：できた動画が地味すぎる。これで合っている？

対処：合っています。自社ブランドが「白ベース・影ゼロ・角ゼロ・アクセント最小」型であれば、動画も静かに出るのが正しい結果です。派手にしたい場合はプロンプトに「今回は frame.md を無視して〜」と書き足せば派手な版も作れます。ただし、落ち着いた雰囲気の動画は、商品やサービスの説得力を出す用途では実は効果が高い傾向があります

Step 8｜実用テスト（自社商品・サービスの告知動画）※本編のメイン工程

Step7までで自社ブランドの下準備が整いました。ここから、実際に発信で使う動画を作ります。

準備するもの（作業前にそろえてください）

  1. 自社サービスの実物スクリーンショット 3〜4枚：画面の入力→処理→結果の流れが分かるもの
  2. BGM：AIに生成させるか、手持ちの利用OKな音源
  3. （任意）人物写真：顔出しできる場合

スクリーンショットを選ぶ基準

  • 入れるもの：機能や使い方が伝わる画面（メイン画面・操作フォーム・出力結果など）
  • 入れないもの：ログイン画面・エラー画面・管理設定画面

個人情報のマスク処理（必ず実施）

スクリーンショットに実在するクライアント名・実際のメールアドレス・実際の担当者名が写り込んでいる場合は、動画に使う前に必ず黒塗り・白塗りで隠してください。Claude Codeに「このスクリーンショットの◯◯の部分を黒塗りしてください」と頼めば処理してもらえます。

そのまま貼り付けるプロンプト（雛形）

[ ] で囲まれている部分をすべて自社の内容に書き換えてから使ってください。それ以外の構成・秒数はそのまま使えます。

/hyperframes
frame.md に従って、30秒の告知動画を1920x1080で作ってください。
テーマは「[あなたのサービス名 or 業界向けカテゴリ]」の告知。

素材：
- ~/[作業フォルダ]/screenshots/ 配下の画像を使ってください：
  - 01_[画面1].png：[画面の内容]
  - 02_[画面2].png：[画面の内容]
  - 03_[画面3].png：[画面の内容]
  - 04_[画面4].png：[画面の内容]

構成：

0-3秒｜白背景、上部に小さくeyebrow「[英字ラベル]」
      中央に「[問題提起の1行]」を静かにフェードイン

3-7秒｜白背景のまま、中央下寄りに3行を1.3秒間隔でフェードイン
      「[痛みの列挙1]」
      「[痛みの列挙2]」
      「[痛みの列挙3]」

7-10秒｜画面リセット、中央大きく「[転換の1文]」
       その1秒後、下に少し小さめで「[余韻の1文]」

10-13秒｜画面が[ブランドの濃色]にゆっくり切り替わり、
       白文字で大きく中央「[サービス名]」
       その下に静かに「[サービスの一言説明]」

13-19秒｜白背景に戻り、スクショ4枚をカード風に順番に見せる。
        1pxヘアライン枠、影なし、角ゼロ、画面中央大きめ配置。
        クロスフェードで滑らかに切替：
        - 13-14.5秒｜01_[画面1].png（キャプション「[何を伝えるか]」）
        - 14.5-16秒｜02_[画面2].png（キャプション「[何を伝えるか]」）
        - 16-17.5秒｜03_[画面3].png（キャプション「[何を伝えるか]」）
        - 17.5-19秒｜04_[画面4].png（キャプション「[何を伝えるか]」）

19-23秒｜画面リセット、白背景に中央大きく
       「[サービスが実現するビジョンの1文]」

23-27秒｜白背景、上部にeyebrow「[CTA英字ラベル・例：TESTERS WANTED]」
       中央「[CTA日本語・例：テスター募集中]」
       その下に小さく「[LP or 申込 URL]」

27-30秒｜静かにフェードアウト、最終フレームに小さく中央「[ブランド名]」のみ残す

トーン厳守：
- frame.md のモーション言語通り
- 派手な回転・バウンド・エフェクトは禁止
- フェードとクロスフェード中心、ゆるやかなスケールのみ許可
- ヘアライン以外の装飾禁止（影ゼロ・角ゼロ）

BGM：
Lyria（音楽生成AI）で生成してください。
「[BGMの雰囲気指定・例：ピアノ中心の静かなアンビエント、テンポ 60-70 BPM、ドラムやシンセの派手さなし]」。
音量は控えめで、文字と映像が主役に見える程度。最後1秒でフェードアウト。

表示されるはずの画面

30秒の動画ファイル（.mp4）が完成します。自社ブランドの色・フォントで、スクリーンショット・BGM入りの告知動画になっています。

よくある質問と対処法

文字だけでなく画像や人物写真も入れられますか
入れられます。5種類の選択肢があります：AI生成イラスト／AI生成写真（人物は「AI感」が出やすいため注意）／利用OKなストック写真／実物スクリーンショット（最もおすすめ）／アイコン・図解
スクリーンショットは何枚必要ですか
3〜4枚で十分です。「入力→処理→出力」の流れが伝わる枚数が目安です
20秒より長くできますか
できます。30〜90秒が扱いやすい長さです。SNS投稿では30秒前後が最も伝わりやすく、60秒を超えると視聴離脱が増える傾向があります
BGMは入れられますか。無音でもいいですか
入れられます。方法は3つ：①AIに雰囲気を伝えて生成させる（推奨・プロンプトに「BGMを[雰囲気]で」と書くだけ）②手持ちの音源ファイルの場所を指定する③利用OKな音源を自分でダウンロードして指定する
AI生成のBGMは商用利用・SNS投稿してよいですか
生成に使うサービスによって条件が異なります。必ず確認してから公開してください。2026年8月時点で確認できている条件：Gemini API経由のLyria（音楽生成AI）は商用利用OK・SNS投稿OK・クレジット表記不要です（Gemini API利用規約より）。「人間が作ったと偽って人をだます目的」でなければ問題ありません。より確実に条件を確認したい場合は、YouTubeオーディオライブラリ・Epidemic Sound・Artlistなど商用利用が明記された音源を使ってください

Step 9｜縦型9:16展開（SNS向け）

この工程で何をするか

Step8で作った横型動画の内容を、Instagram Reels・TikTok・YouTube Shortsなど縦型SNS向けのサイズに作り直します。

準備するもの（追加）

  • （任意）人物写真1枚：「これ、僕が自分のために作りました。」のような"作った人"を見せるカットに使います

縦型で変わる点

  • サイズは1080×1920に変わります
  • 文字は横一列に詰め込まず、意味のかたまりごとに縦に積んでください（横画面用の文字量をそのまま流用すると読みにくくなります）
  • スクリーンショットは画面の上半分、説明文（キャプション）は下半分に配置します

巻末｜この先にあるもの（本マニュアルの範囲外）

ここまでは「自分の手で動画を1本作れる状態」がゴールでした。この先には、動画制作を「自分1人ができる」から「組織の仕組みとして定着させる」段階があります。具体的には、動画制作の専任担当と品質チェック担当を設け、誰が依頼しても同じ品質・同じブランドで動画が出てくる体制を作る、というものです。

  • 無料版（本マニュアル）で到達する状態：単発の告知動画1本を、自分の手で作れる状態
  • その先で実現する状態：複数の商品・チームでの運用まで見据えた、動画制作が組織の仕組みとして回っている状態

この先の進め方に関心がある場合は、別途ご案内します。

全体Q&A（詰まりやすいポイントまとめ）

Claude Code以外のツールでも同じことができますか
使用しているスキル群は、Claude Code以外の一部のコーディング支援ツールでも動作すると公式に案内されています。ただし本マニュアルはClaude Code前提で書かれているため、他ツールをお使いの場合は表示や手順が一部異なる可能性があります
エラーメッセージが出て何をすればいいか分からない
対処：エラーメッセージ全文をそのままコピーして、Claude Codeに貼り返してください。「このエラーが出ました。直してください」と伝えるだけで、多くの場合は解決します
途中で作業を中断してしまった。最初からやり直しですか
対処：やり直しは不要です。作業フォルダ（~/HyperFrames_Trial）に、ここまで作ったファイル（DESIGN.md・frame.md・動画ファイル）がそのまま残っています。続きのStepから再開してください
